# Matthew Yang · 猎头顾问介绍页（候选人视角）

面向**候选人（求职者）**的单页网页。目标不是"我要找一份工作"，而是"把简历交给我，我帮你找到值得去的团队"。
纯静态、零依赖、单文件，可直接托管在 GitHub Pages。

## 页面定位

| 面向谁 | 想达成什么 |
|---|---|
| 算法 / 具身智能方向的工程师（候选人） | 让 TA 愿意把简历交给你、愿意先聊一次 |

因此页面结构是「服务价值 → 专注赛道 → 合作流程 → 信任背书 → 隐私承诺 → 常见问题 → 联系方式」，
而不是简历常见的「教育背景 → 工作经历 → 自我评价」。原求职版简历仍在 git 历史中（commit `ebea1df`）。

## 页面模块

1. **首屏主张**：一句话说清价值（帮工程师找到值得去的团队），3 个行动按钮，2 个数字（80 万业绩 / 2 条赛道）
2. **我能帮你什么**：4 张价值卡——只推匹配岗位、帮你讲清项目、面试陪跑、谈薪依据
3. **专注赛道**：算法 / 具身智能两条线，各配真实岗位关键词（SLAM、运控、VLA、Sim2Real 等）
4. **合作流程**：STEP 01–06，从初次沟通到入职跟进
5. **关于我**：人力资源本科 + 2025 入行 + 80 万业绩 + 一段个人观点（信息对称）
6. **我对你的承诺**：隐私与简历处理四条硬承诺（候选人最在意的部分）
7. **常见问题**：5 条 FAQ（收费吗、会不会乱投、暂时不跳槽、城市与客户、非名校有没有机会）
8. **联系我**：邮箱（一键复制 / 直接发信）、电话、微信

## 部署到 GitHub Pages

### 方式一：网页上传（最简单）

1. GitHub 新建仓库，命名如 `resume`，可见性选 Public
2. 仓库 → `Add file` → `Upload files` → 拖入 `index.html`
3. `Settings` → `Pages` → Source 选 `Deploy from a branch`，Branch 选 `main` / `root` → Save
4. 约 1 分钟后访问：`https://<你的用户名>.github.io/resume/`

### 方式二：命令行推送

```bash
cd resume-web
git remote add origin https://github.com/<你的用户名>/resume.git
git branch -M main
git push -u origin main
```

推送后在 `Settings → Pages` 开启分支部署。

### 方式三：GitHub Desktop

用 GitHub Desktop 打开本目录 → Publish repository → 勾 Public → 发布后网页端开启 Pages。

> 仓库若命名为 `<你的用户名>.github.io`，访问地址直接是 `https://<你的用户名>.github.io/`。
